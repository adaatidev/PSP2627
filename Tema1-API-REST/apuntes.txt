Dos orígenes de datos distintos: FastAPI combina automáticamente dos fuentes en la misma función:

id: int lo extrae de la URL (/users/2).

datos: UserPatch lo extrae del cuerpo (Body) JSON de la petición, donde todos los campos son opcionales.

2. Búsqueda con enumerate()
Python
for posicion, usuario in enumerate(users_list):

En las rutas GET anteriores bastaba con for usuario in users_list:, porque solo querías leer el objeto. Aquí necesitas sustituirlo dentro de la lista, así que enumerate() te entrega dos variables en cada vuelta:

usuario: el objeto User en esa posición.

3. Filtrar solo los cambios reales (model_dump)
Python
cambios = datos.model_dump(
    exclude_unset=True,
    exclude_none=True
)
Esta es la parte clave del PATCH. Si el cliente envía únicamente {"age": 25}, el objeto datos (UserPatch) tendrá name=None, surname=None y age=25. Si no filtraras esos None, borrarías el nombre y apellido reales de María:

exclude_unset=True: Descarta cualquier campo que el cliente no haya incluido en el JSON enviado.

exclude_none=True: Descarta también los campos que el cliente haya enviado explícitamente como null, evitando que rompan los campos obligatorios de User.

Con el ejemplo {"age": 25}, la variable cambios será exactamente el diccionario {"age": 25}.

4. Combinar datos antiguos con nuevos y revalidar
Python

datos_actualizados.update(cambios)

usuario.model_dump(): Convierte al usuario original de la lista en un diccionario: {"id": 2, "name": "María", "surname": "Martínez", "age": 20}.

.update(cambios): Sobrescribe en ese diccionario únicamente las claves que existan en cambios. El diccionario pasa a ser {"id": 2, "name": "María", "surname": "Martínez", "age": 25}.

User(**datos_actualizados): Desempaqueta el diccionario resultante para crear un nuevo objeto User, garantizando que Pydantic vuelva a validar que el objeto final cumple todas las reglas del modelo.

Si encuentra el usuario, reemplaza el elemento antiguo en users_list[posicion] por usuario_modificado y lo devuelve como respuesta JSON.

socket.AF_INET y socket.SOCK_STREAM: El primer argumento indica que se usará IPv4 (127.0.0.1) y el segundo especifica que el protocolo de transporte será TCP (fiable y orientado a conexión, frente a SOCK_DGRAM que sería UDP).

//  CLASE ELFO CON ENUM
Cómo aplicarlo en routers/elfs.py
Python
from enum import Enum
from fastapi import APIRouter, HTTPException
from pydantic import BaseModel, Field

router = APIRouter()


class Turn(str, Enum):
    MORNING = "morning"
    AFTERNOON = "afternoon"
    NIGHT = "night"


class Elf(BaseModel):
    id: int
    name: str
    turn: Turn
    manufactured_toys: int = Field(ge=0)


elfs_list = [
    Elf(id=1, name="Name1", turn=Turn.MORNING, manufactured_toys=10),
    Elf(id=2, name="Name2", turn=Turn.AFTERNOON, manufactured_toys=65),
    Elf(id=3, name="Name3", turn=Turn.NIGHT, manufactured_toys=40),
]
Detalles clave a tener en cuenta
Doble herencia (str, Enum): Es imprescindible heredar de str además de Enum. Si solo heredas de Enum, Pydantic y Swagger no lo tratarán como una cadena JSON estándar.

Uso en endpoints (también sirve en filtros): Si creas un endpoint para filtrar por turno, puedes usar Turn como tipo del parámetro y en /docs también te saldrá el desplegable:

Python
@router.get("/by-turn")
def get_elfs_by_turn(turn: Turn):
    return [elf for elf in elfs_list if elf.turn == turn]
Comparaciones y creación: Al crear los objetos iniciales en elfs_list, puedes usar Turn.MORNING (más limpio y con autocompletado) o directamente el texto "morning", ya que Pydantic lo convertirá al Enum automáticamente.
